# Решения

Открывай после того, как посидел над задачей сам. Проверки в скриптах устроены
так, что «прошло» действительно означает «правильно», — поэтому подглядывание
здесь ничего не ускоряет, кроме потери самого упражнения.

## 00 — сборка контура

```python
system = Pendulum()
integrator = RK4Integrator()
controller = LinearFeedbackController(K)
closed = rollout(system, controller, integrator, [0.3, 0.0], 1e-3, 5000)
```

Единственная тонкость — порядок аргументов: сначала три блока, потом начальное
условие, шаг и число шагов.

## 01 — свой Controller

```python
    def act(self, t, x_hat):
        theta = x_hat[..., 0]
        dtheta = x_hat[..., 1]
        return np.stack([-self.kp * theta - self.kd * dtheta], axis=-1)
```

`np.stack([...], axis=-1)` делает всю работу по соблюдению соглашения о пачках:
для состояния `(2,)` компоненты — скаляры и на выходе `(1,)`, для пачки `(M, 2)`
компоненты — векторы `(M,)` и на выходе `(M, 1)`. Написать
`np.array([-kp*theta - kd*dtheta])` тоже даст правильный ответ для одного
состояния, но на пачке вернёт `(1, M)` вместо `(M, 1)` — и проверка это поймает.

Часть B:

```python
    def act(self, t, x_hat):
        s = np.sign(self.kp * x_hat[..., 0] + self.kd * x_hat[..., 1])
        return np.stack([-self.u_max * s], axis=-1)
```

Выражение `kp*theta + kd*dtheta` называется поверхностью скольжения. Регулятор
всё время толкает состояние к ней, перескакивая через неё каждый шаг — отсюда
дребезг. Это простейший скользящий режим; систематически — Utkin, *Sliding Modes
in Control and Optimization*, гл. 1–2.

## 02 — свой Integrator

```python
    order = 2

    def step(self, f, t, x, u, dt):
        x = np.asarray(x, dtype=float)
        k1 = np.asarray(f(t, x, u), dtype=float)
        k2 = np.asarray(f(t + 0.5 * dt, x + 0.5 * dt * k1, u), dtype=float)
        return x + dt * k2
```

Идея: Эйлер оценивает наклон в начале интервала и потому систематически
промахивается; средняя точка сначала делает пробный полушаг, меряет наклон
посередине и уже им проходит весь шаг. Один лишний вызов `f` — плюс порядок.

Типичная ошибка — вернуть `x + dt/2 * (k1 + k2)`: это метод Хойна, тоже второго
порядка, и проверка на порядок его пропустит, а проверка «точнее Эйлера, грубее
RK4» — тоже. Формально это другая схема, но не ошибка.

## 03 — своя System

```python
    @property
    def u_bounds(self):
        if self.p.u_max is None:
            return None
        return (np.array([-self.p.u_max]), np.array([self.p.u_max]))

    def f(self, t, x, u):
        theta = x[..., 0]
        dtheta = x[..., 1]
        p = self.p
        ddtheta = (p.m * p.g * p.l * np.sin(theta)
                   - p.cq * dtheta * np.abs(dtheta)
                   + u[..., 0]) / p.I
        return np.stack([dtheta, ddtheta], axis=-1)
```

Два места, где легко ошибиться:

* **`dtheta * abs(dtheta)`, а не `dtheta**2`.** Сопротивление направлено против
  движения, то есть член обязан быть нечётным по скорости. С `dtheta**2` при
  движении назад сила разгоняет, и проверка на монотонное убывание энергии
  падает. Физически это квадратичный закон Ньютона (`Re` порядка тысяч), в
  отличие от линейного стоксова трения при малых `Re` — Landau & Lifshitz,
  *Fluid Mechanics*, §24.
* **`+ m g l sin(theta)`, а не `-`.** Угол отсчитывается от ВЕРХНЕЙ вертикали,
  поэтому гравитация уводит от равновесия. Знак минус даст обычный висящий
  маятник, который устойчив сам по себе, и проверка на совпадение с библиотечным
  `Pendulum` это поймает.
